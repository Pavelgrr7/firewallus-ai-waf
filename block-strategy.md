# Три уровня блокировки. В Redis хранится не один чёрный список, а три разных. Ktor-фильтр при каждом запросе проверяет все три.
## 1. Уровень: Бан по авторизации
Если запрос идет к защищенному API и у пользователя есть токен (например, JWT в заголовке Authorization), вытаскиваем из него User-ID (или хэш токена) и шлем нейронке.
Действие: Если нейронка видит инъекцию, она банит конкретный User-ID.
Итог: Хакер забанен. Все остальные пользователи публичного Wi-Fi работают спокойно. Сменить JWT за секунду хакер не сможет (ему надо заново регистрировать аккаунт).
## 2. Уровень: Бан по Fingerprint (Защита от ленивых скриптов)
Если пользователь анонимный, нейронка вычисляет Fingerprint (тот самый hash(IP + User-Agent + Accept-Language)).
Действие: Если пошли атаки, нейронка кидает в Redis этот Fingerprint.
Итог: Банится только этот конкретный браузер хакера. Остальные люди в кафе с того же IP сидят с других телефонов и браузеров — их пускает.
## 3. Уровень: Бан по IP
Но хакер понял, что его банят, и включил рандомизацию User-Agent. Теперь он генерирует новый Fingerprint каждую секунду с одного и того же IP.
Действие: На стороне Python-сервиса считаете Risk Score (штрафные баллы) для IP-адреса.
Логика: Если с одного IP-адреса за 1 минуту пришло 20 разных плохих Fingerprints — это 100% ботнет, сканер или автоматизированная атака. Сопутствующий урон отходит на второй план — ради спасения базы данных мы баним весь IP на уровне L3/L7.
